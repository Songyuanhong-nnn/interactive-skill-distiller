# 校验清单

P4 阶段逐项跑 A–D；B 路线交付前跑 E；C 路线交付前跑 F。分三级：**硬性**（不过就不输出）、**建议**（不过要说明理由）、**会话特有**（只有在多轮访谈里才需要注意）。

---

## A. frontmatter 硬性检查

### name
- [ ] 正则通过：`^[a-z0-9]+(-[a-z0-9]+)*$`
- [ ] 长度 1–64
- [ ] 无大写、无下划线、无空格
- [ ] 非连字符开头/结尾，无连续连字符 `--`
- [ ] 与父目录名完全一致

### description
- [ ] 非空，长度 ≤ 1024
- [ ] 同时包含 **做什么（WHAT）** 和 **何时用（WHEN）**
- [ ] 含 3–5 个用户真实会说的触发短语（不是自造术语）
- [ ] 不含"强大""高效""全方位"这类空词

### YAML 语法
- [ ] 用空格缩进，无 Tab
- [ ] 含 `:` `#` `{` `}` 的字符串已加引号
- [ ] 多行用 `>-` 或 `|` 块标量
- [ ] 无行尾空白

---

## B. 正文硬性检查

### 用途与边界
- [ ] 用途段 2–4 句，能被一个外行读懂
- [ ] "何时用" ≥ 2 个具体场景（不是"需要时"这种）
- [ ] "何时不用" 至少 1 条，且写清与相邻 skill 的分工

### 工作流
- [ ] 步骤 ≥ 3
- [ ] 每步**原子化**：一个明确动作，AI 不必追问就能执行
- [ ] 每步有验证条款（如何确认这步成了）
- [ ] 有 if/then 形式的决策点
- [ ] 流程闭环：起点 → 步骤 → 终验 → 终态
- [ ] 代码块有语言标识

### 命令与示例
- [ ] 命令可直接复制运行
- [ ] 占位符统一 `<大写下划线>` 格式
- [ ] 无硬编码的密钥、绝对个人路径

### 易错点
- [ ] ≥ 1 条，格式 `❌ 错法 → ✅ 对法`
- [ ] 至少 1 条来自真实访谈（不是通用套话）

### 参考
- [ ] 章节存在（没有就写"无"）
- [ ] URL 可访问，链接文字有描述性

---

## C. 质量建议项

- [ ] 整个 SKILL.md 自包含：核心理解不依赖外部文件
- [ ] UTF-8 编码
- [ ] 无 emoji（❌/✅ 除外）
- [ ] 语气是操作指令，不是散文
- [ ] 详细表格/长清单已拆到 references/，主文件保持可扫读
- [ ] 主文件行数 ≤ 400（超过说明该拆）

---

## D. 会话特有检查（多轮蒸馏才会踩）

- [ ] **失忆 agent 测试**：假装从没见过这场对话，只拿这份 SKILL.md，能否不问任何问题跑完？
- [ ] 所有 `inferred`（你推断的）内容，要么已在骨架里被用户确认，要么在文中标注了不确定
- [ ] 用户在访谈中说过的**具体样例**（文件名、字段名、阈值）已落进正文，没有丢
- [ ] 被否决的方案没有偷偷出现在正文里
- [ ] 触发词与用户原话有重合（用户怎么描述这件事，就用那句话的片段）
- [ ] 版本号与 `state.yaml`、`iterations/` 一致

---

## E. B 路线交付物校验（交付前跑）

- [ ] 交付物能直接打开/运行，不是"还需要你再加工一下"的半成品
- [ ] 对照 `goal.md` 的三行判据逐条过：形态对、读者能用、通过线过了
- [ ] 明确标出"我在这些地方不确定"至少 1 条（一条都没有，说明你在猜，不是在校准）
- [ ] 没有把推断当事实：用户没说过的设定或数据，要么标注，要么删掉
- [ ] 篇幅与任务匹配，不注水凑字数
- [ ] 下一步只有一句，且是等用户确认的，不是自动继续

---

## F. C 路线计划校验（交付前跑）

- [ ] 给了至少 2 条真正不同的路线，不是同一方案的微调
- [ ] 每条路线都写了代价与风险，能说出"什么条件下选它"
- [ ] 里程碑 3–7 个，每个有具体产出物
- [ ] 每个里程碑有可被第三方验证的判据（"完成用户模块"不算）
- [ ] 标了关键路径，以及至少 1 个回滚点
- [ ] 没有"加强""提升""优化""推进"这类无法验收的词
- [ ] 计划受约束约束：人手、时间、预算对得上，不是空想
- [ ] 一屏能看完，不用目录导航

---

## 不通过怎么办

| 问题 | 处理 |
|---|---|
| 硬性项不过 | 就地修，不输出，不解释"这是小问题" |
| 建议项不过 | 可以放行，但在收尾时告诉用户"这里我简化了，因为…" |
| 会话特有项不过 | 说明访谈有缺口，回 P2 补对应维度，不要硬写 |

---

## 常见返工原因（按频率排序）

1. 步骤不原子 —— 一步塞了 4 个动作，AI 执行时会漏
2. 缺验证条款 —— AI 做错了自己不知道
3. description 只写 WHAT 不写 WHEN —— 该触发时不触发
4. 易错点是通用套话 —— "注意路径"这种，没有信息量
5. 没有边界 —— 什么都能干，结果什么都干不好
